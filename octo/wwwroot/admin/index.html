Navidrome library
This server has more than one library. Pick the one Octo should download into; otherwise it uses whichever Navidrome lists first.
Auto-detect download path from Navidrome
Octo asks Navidrome where its music folder is and writes there, so downloads always land where Navidrome scans. Only adopts a path Octo can see; otherwise it uses the field below.

Path INSIDE the Octo container where downloaded files land (default /music, backed by the DOWNLOAD_PATH bind mount). Streams & downloads

Choose how missing tracks play and where hearts acquire permanent copies.

Stream source

When a track is missing
YouTube starts immediately and is the default. Soulseek download waits for a lossless copy before playback begins.
YouTube shim URL
The yt-dlp sidecar that resolves and streams missing tracks. The default works inside the Docker network.
Soulseek connection
Octo downloads the lossless copy through slskd before returning audio. Connection credentials, search limits, and transfer timeouts stay on the existing Soulseek page.
Lossless wait timeout seconds
Only with lossless waiting enabled. 0 waits indefinitely; a positive value falls back to the YouTube preview after this many seconds while acquisition continues.

Heart acquisition

Heart download priority
Choose which sources handle song and album hearts. Octo tries each enabled source from top to bottom and stops at the first success. Only Soulseek is enabled by default.

Metadata

Tag language
Language for genre and other text fetched from metadata providers (Deezer, Last.fm) and written into a download's tags. Without it, providers pick a language from the server's IP address. Two-letter code like en, de, fr; empty lets the provider decide. New lookups use it right away; results cached in the last 12 hours keep their old language until they expire.

Radio basics

Song radio is a one-time queue requested by a client. Dynamic and pinned radio are reusable stations.

Enable Last.fm radio
Master switch for start-from-a-song queues and all dynamic or pinned stations.
Tracks per station or queue
Maximum tracks in start-from-a-song queues and in dynamic or pinned station snapshots.
Last.fm lookup cache (hours)
How long Octo reuses recommendation responses across radio features.
Refresh stations every (hours)
Rebuilds dynamic and pinned station queues in the background. The current snapshot stays playable until its replacement is ready. Default: 12 hours.

How stations play

Applies to dynamic and pinned stations only. Enable either playback method or both; song radio remains a client-created track queue.

Playlist method
Shows each station in the client's Playlists section. This provides full track controls and preserves normal local-song quality; heart a discovery track to fetch a permanent lossless copy.
Streaming method
Shows each station in the client's Radio section as one continuous MP3 stream. Tracks are transcoded to the quality selected below.
Radio streams cannot add songs to your library. A client sees one continuous stream rather than individual songs, so liking or hearting the current track cannot trigger an Octo download. Open the station in Playlists when you want to heart a song and add it.
Internet radio quality
MP3 bitrate for new continuous streams. Reconnect to apply a change. This does not affect playlist playback or downloaded quality.
Now-playing metadata
Embeds Octo's existing station artist and title in the MP3 stream for radio clients that request ICY metadata. Reconnect after changing this setting.

Dynamic stations

Builds read-only stations from each listener's completed plays. Listening history stays private in Octo.

Enable dynamic stations
Starts with Starter Radio, then grows into Your Mix, discovery, artist, and genre stations.
Discovery balance
Percentage of Your Mix reserved for less-familiar recommendations.
Personalization threshold and history
Completed plays before Your Mix
Before this many completed plays, Octo offers Starter Radio. Afterward it can build Your Mix plus discovery, artist, and genre stations. Default: 10 plays.
Keep completed plays for (days)
Older plays stop influencing dynamic stations and are removed from Octo's local listening history. Downloaded music is unaffected. Default: 90 days.

Pinned stations

You choose fixed names and tag categories; Octo refreshes the tracks inside them automatically. Add up to 12, each combining up to five Last.fm tags.

Show pinned stations
Hiding these stations preserves their definitions and snapshots.

Raw config

Edit the settings file directly. Same JSON the form-by-form UI writes to — useful for power-users who'd rather hand-write a section than click through tabs, or for diffing/copying config across hosts.

File path

The file lives at /app/config/settings.json inside the container. The host bind-mount is at ./octo-config/settings.json next to your docker-compose.yml — you can vim/nano it there too. Changes hot-reload within ~500ms; settings flagged restart-required still need a restart.

settings.json

Top-level keys: Subsonic, Library, Soulseek, Lidarr, YouTube, LastFm, Metadata. Radio remains inside LastFm; pinned rows are the ordered LastFm.DiscoveryStations array and should be edited as complete objects with stable Id, Name, Enabled, and Tags fields. Anything you set here overrides the corresponding env var until removed.

Config sources

What value the app actually sees for each setting, after merging env vars and the settings file. Most settings now apply the moment you save. The few that cannot are marked restart required where you change them: the download path, the slskd connection, and the shim URL are all read once while the app starts.

Resolution order (highest first)

  1. settings.json — what the admin UI writes to. Highest priority.
  2. Environment variables — set in docker-compose.yml / .env at container startup.
  3. appsettings.json — built-in defaults shipped with the image.

About

What this is and where things live.

Octo is a Subsonic API proxy that augments your existing Navidrome library with discovery and on-demand downloading. Search includes external recommendations alongside your local songs; "Radio" on any song fans out via Last.fm and previews via YouTube; star music you don't own and Octo acquires it through Soulseek or your existing Lidarr server.

Version

You are running Octo unknown. Include this in any bug report. Releases are dated, so 2026.07.29 is the release cut on that day.

Settings file

Anything you change in this UI is persisted to /app/config/settings.json. That file overrides env vars on next read. Editing it by hand also works — changes hot-reload.

Hot-reload vs restart

Most settings (storage mode, folder structure, filters) take effect immediately. Settings flagged restart required bake into HTTP clients at startup; use the Restart button in the sidebar to apply them.

Sign in to browse
Browsing folders needs a Navidrome admin account. Octo checks it with your Navidrome server and never stores it.
